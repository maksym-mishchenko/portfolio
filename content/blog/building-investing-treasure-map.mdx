A few weeks ago I had a simple idea: what if learning about investing felt like exploring a map in a video game?

Not another boring course with slides. Something visual, interactive, with a dark mysterious vibe. I went with Stranger Things as the theme — because why not make ETFs feel dangerous?

## The Concept

Seven zones, each covering a core investing topic:

1. **The Upside Down** — What is investing and why start?
2. **Hawkins Lab** — Risk vs. reward fundamentals
3. **The Mind Flayer's Lair** — Asset classes explained
4. **Eleven's Hideout** — ETFs and index funds
5. **The Gate** — Building your first portfolio
6. **Starcourt Mall** — Tax-advantaged accounts
7. **The Void** — Behavioral finance and staying the course

Each zone has a lesson and a quiz. You unlock zones sequentially. Progress is tracked in localStorage — no database needed.

## Tech Stack

- **Next.js 16** with TypeScript (App Router)
- **Vercel** for hosting
- **Tailwind CSS** for the dark Stranger Things aesthetic
- **Framer Motion** for animations and particle effects

The whole thing is a single-page app with dynamic zone rendering. No backend database — quiz progress lives in the browser.

## Security Was the Fun Part

After shipping the initial version, I did a proper security audit. Found some real issues:

**Session cookies were just base64-encoded JSON.** Anyone could forge them. Fixed with HMAC-SHA256 signing using `crypto.createHmac()`. Now cookies look like `{data}.{signature}` and the server validates the signature with constant-time comparison.

**The quiz API leaked correct answers.** If you submitted a wrong answer, the response included which answer was right. Fixed by only revealing `correctIndex` after you answer correctly (or pass the whole quiz).

**No rate limiting anywhere.** Added in-memory rate limiters to login (5/min per IP) and feedback (1 per 10 min per IP). Good enough for a serverless app.

**Missing security headers.** Added CSP, X-Frame-Options (DENY), X-Content-Type-Options (nosniff), and a strict Referrer-Policy.

The full commit was satisfying — HMAC cookies, rate limiting, input validation, answer protection, security headers, and a Next.js upgrade that patched 4 CVEs. All in one PR.

## Community Features

I wanted to know if anyone actually used the thing, so I added:

- **Progress bar** showing "X/7 zones completed" at the top
- **Feedback buttons** — "❤️ I liked it", "📬 Want more content", and "🏆 I finished it all!" (the last one only appears when you complete all zones)
- **Telegram notifications** — every feedback click pings me on Telegram
- **Persistent stats** — feedback counts stored on my VM via a tiny Node.js API, displayed as community counters on the page

The stats flow: Vercel → Telegram + VM API → JSON file. Simple, free, persistent.

## What I'd Do Differently

**Start with the security audit.** I shipped first, audited later. For a public app, that's backwards. The HMAC cookies and answer protection should have been day-one decisions.

**Keep it simple.** No database, no auth requirement for visitors, no user accounts. The app does one thing well. Every feature I considered adding ("dark mode toggle", "leaderboard", "social sharing") would have made it worse, not better.
