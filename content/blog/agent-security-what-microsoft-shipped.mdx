Microsoft shipped agent identities in April 2026.

Doesn't solve the hard problem.

## What Entra Agent ID provides

Three pieces:

**1. Identity framework**

Blueprints for creating agent IDs with parent-child relationships. Works across Microsoft and non-Microsoft platforms. OAuth 2.0, MCP, A2A protocols out of the box.

**2. Conditional Access**

Adaptive policies for agents. Risk-based auth, geo-fencing, device compliance checks. Same engine that already gates user sessions.

**3. Audit logs**

Every agent action tracked. Who authorized it, when it ran, what it called. Governance layer for compliance.

## What Entra does NOT provide

**1. Jailbreak prevention**

No built-in guardrails to stop adversarial prompts from overriding instructions. The model still does whatever the prompt says.

**2. Tool permissions**

No deterministic boundaries for which tools an agent can call or what data it can access. No scoping beyond "this agent can call APIs."

**3. Agent-specific DLP**

No reactive scanning for sensitive data in agent prompts or outputs. Standard DLP doesn't see inside the agent's reasoning chain.

The gap: **Identity is solvable. Enforcement is not.**

## The architecture pattern that works

Microsoft's own security team documented this after GitHub Copilot CLI went from 12 security incidents per month to zero.

Three-layer defense:

### 1. Identity (Entra gives you this)

Every agent gets a managed identity. OAuth tokens carry claims. You parse `scp` before using the token. Conditional Access gates risky contexts.

### 2. Enforcement (you build this)

**Deterministic shell around the agent core.**

Code-enforced boundaries, not prompt-enforced. If a tool shouldn't be called, it's not in the allowlist. If a file path is out of scope, the validation function rejects it before the agent sees the response.

Example from our stack:

```python
class ToolExecutor:
    ALLOWED_TOOLS = {
        "read_file", "write_file", "terminal",
        "web_search", "web_extract"
    }
    
    def execute(self, tool_name: str, params: dict):
        # Double validation
        if tool_name not in self.ALLOWED_TOOLS:
            raise ToolNotAllowedError(tool_name)
        
        # Scope check before execution
        if tool_name == "terminal":
            self._validate_command(params["command"])
        
        return self._run_tool(tool_name, params)
```

The agent can ask for anything. The shell only runs what's allowed.

### 3. Observability (you build this)

Log everything. Every tool call, every decision, every token used.

When something breaks the rules, kill the session. Alert immediately. Don't wait for a human to notice.

## What you ship yourself

**Deterministic shell** — allowlists, validation, scoping

**Tool validation** — double-check before execution

**Observability** — log, alert, kill fast

If it matters, don't trust the prompt. Move it into code.

## The lesson GitHub Copilot CLI taught Microsoft

12 incidents per month → 0.

Not by better prompts. By deterministic enforcement.

The agent runs in a locked-down shell. Tool calls go through validation. Risky patterns get blocked before they execute.

Entra Agent ID handles the identity layer. The enforcement layer is code you write.

The architecture pattern Microsoft documented works. It's just not a product you buy. It's a discipline you adopt.

Enforcement = build yourself.
